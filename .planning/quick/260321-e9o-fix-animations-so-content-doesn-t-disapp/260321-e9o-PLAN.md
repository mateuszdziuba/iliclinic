  <action>
The root cause: every page uses `gsap.fromTo(el, { opacity: 0, y: N }, { opacity: 1, y: 0, ... })`. If GSAP script hasn't loaded, if ScrollTrigger doesn't fire (element already in viewport when observer initializes), or if Lenis smooth scroll conflicts with ScrollTrigger timing, elements stay at `opacity: 0` forever.

Fix strategy — make animations progressive enhancement:

1. **For hero entrance animations** (non-scroll-triggered, run on load): These are generally fine since they fire immediately. But add a CSS safety net. In each page's `<script>` block, BEFORE the `gsap.fromTo` calls, add:
   ```js
   // Safety: ensure all animated elements become visible even if GSAP fails
   const safetyTimeout = setTimeout(() => {
     document.querySelectorAll('[data-hero-label],[data-hero-title],[data-hero-desc],[data-hero-content],[data-hero-text],[data-hero-image],[data-hero],[data-scroll-fade]').forEach(el => {
       (el as HTMLElement).style.opacity = '1';
       (el as HTMLElement).style.transform = 'none';
     });
   }, 2000);
   ```
   Then after the last hero `gsap.fromTo`, add `clearTimeout(safetyTimeout);` (since GSAP ran successfully).

2. **For `[data-scroll-fade]` elements** (scroll-triggered): The main culprit. These use ScrollTrigger and if the element is already in viewport on page load, ScrollTrigger may not fire the entrance. Fix by changing from `gsap.fromTo` to `gsap.from` with `scrollTrigger: { trigger: el, start: 'top 88%', once: true }` AND adding `immediateRender: false` so GSAP doesn't set initial state until ScrollTrigger activates. But more importantly, add a CSS `<style>` block that ensures `[data-scroll-fade]` elements start visible:
   ```css
   [data-scroll-fade] { opacity: 1; }
   ```
   Then in JS, only elements NOT yet in viewport get animated. Change the scroll-fade logic on ALL 5 pages to:
   ```js
   document.querySelectorAll('[data-scroll-fade]').forEach(el => {
     const rect = el.getBoundingClientRect();
     const inView = rect.top < window.innerHeight && rect.bottom > 0;
     if (inView) {
       // Already visible — just do a quick fade-in from current position
       gsap.fromTo(el,
         { opacity: 0.3, y: 15 },
         { opacity: 1, y: 0, duration: 0.6, ease: 'power2.out' }
       );
     } else {
       // Not yet in view — use ScrollTrigger
       gsap.set(el, { opacity: 0, y: 35 });
       gsap.to(el, {
         opacity: 1,
         y: 0,
         duration: 1.0,
         ease: 'power3.out',
         scrollTrigger: { trigger: el, start: 'top 88%' },
       });
     }
   });
   ```

3. **For treatment cards** in `zabiegi/index.astro` (line 240-250): Same issue — `gsap.fromTo(cards, { opacity: 0 ...})`. Apply same pattern: check if cards are in viewport, animate from slight fade if yes, set+scrollTrigger if no.

Apply this pattern consistently across all 5 files. Keep the same easing and duration values already in use.
